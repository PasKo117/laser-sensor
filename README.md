### Sick OD mini pro LIB ###
Библиотека и консольный клиент для работы с (пока что) двумя лазерными датчиками SICK OD Mini Pro. Скрипт самостоятельно разворачивает серверную часть (код + установка библиотек, если есть подключение к интернету) на Raspberry Pi 4B, устанавливает защищённое TCP-соединение и предоставляет возможность вывести интерфейс для настройки, калибровки и непрерывного считывания данных.
### 1. Инструкция по запуску и пользованию

* 1. Подготовка окружения
   1. Убедитесь, что на ПК установлен Python 3.7+.
   2. Если в сети платы нет интернета, установите внешне библиотеку на RASP для SSH-деплоя: <pip install paramiko>.
   3. Подключите оба датчика к Raspberry Pi через USB-адаптеры. Проверьте, к каким портам они привязались (“/dev/ttyUSB0” и т.д.).
   4. Убедитесь, что на Pi включён SSH-доступ и он находится в той же сети, что и ПК. (Желательно задать им статический IP)

* 2. Запуск приложения
   1. В # КОНФИГУРАЦИЯ укажите актуальный IP-адрес Pi, логин, пароль и путь для серверного скрипта.
	PI_IP = '192.168.X.X'
PI_USER = 'pi'
PI_PASS = 'raspberry'
PI_SERVER_PATH = '/home/pi/sensor_server.py'
PI_TCP_PORT = 5000
   2. В строке `PI_SERVER_CODE` при необходимости замените `SERIAL_PORT_1` и `SERIAL_PORT_2` на ваши реальные порты.
   3. Запустите скрипт: `python main.py`.
   4. Программа сама подключится к Pi, установит `python3-serial`, выгрузит серверный код, запустит его в фоне и откроет главное меню.

*3. Навигация по главному меню
   1. Пункты `1-3` запускают потоковый режим стрима для одного или обоих датчиков.
   2. Пункты `4-5` открывают меню детальной настройки конкретного датчика.
   3. Ввод `Q` завершает работу программы и корректно закрывает соединение.

*4. Меню настроек датчика
   1. Пункты `1-4` читают текущие данные.
   2. Пункты `5-13` управляют состоянием.
   3. Пункты `14-28` меняют конфигурацию.
   4. После изменения любых параметров обязательно вызовите пункт `5` (Запись в EEPROM), иначе настройки сбросятся при перезагрузке датчика.

*5. Работа в режиме стрима
   1. На экране в реальном времени выводятся значения расстояний и частота обновления (FPS).
   2. `S` — остановить стрим и вернуться в меню.
   3. `P` — поставить стрим на паузу или возобновить.
   4. `B` — выйти из стрима в главное меню.
   5. `Q` — полностью завершить программу.

 
### 2. Описание кода

Код разделён на три логические части: конфигурацию, встроенный сервер для Pi и клиентскую часть с консольным интерфейсом.

1. Встроенный сервер (`PI_SERVER_CODE`)
   1. Код хранится в виде строки и автоматически разворачивается на Raspberry Pi при запуске.
   2. Отвечает за прямое общение с датчиками по Serial, парсинг бинарных пакетов (STX/ETX/BCC).
   3. Слушает TCP-порт, принимает JSON-команды от ПК, выполняет их и возвращает ответ.
   4. Отдельный поток `stream_sender` непрерывно опрашивает датчики и рассылает данные всем подключённым клиентам.

2. Класс “SensorClient” (основной интерфейс)
   1. “deploy_to_pi” — подключается по SSH, ставит "python3-serial", записывает серверный код на диск, убивает старые процессы и запускает новый.
   2. “connect_tcp” — устанавливает TCP-соединение с повторными попытками, запускает фоновый поток прослушки стрима.
   3. “_send_command” — ядро обмена данными. Формирует JSON, отправляет, ждёт ответ, обрабатывает таймауты и автоматически переподключается при обрыве связи.
   4. Группа методов чтения: “measure”, “read_status”, “read_all”, “get_model”. Возвращают сырые данные или словари параметров.
   5. Группа методов управления: “laser_on/off, “zero_reset/restore”, “key_lock/unlock”, “init_sensor”, “write_eeprom”, “dismiss”. Меняют аппаратное состояние или сохраняют конфигурацию.
   6. Группа методов настройки: “set_mode”, “set_sampling”, “set_averaging”, “set_polarity”, “set_alarm”, “set_display”, “set_sensitivity”, “set_threshold”, “set_near/far/obsb/obsb_hyst/hyst/zero_shift”, “set_alarm_hold”. Принимают человекочитаемые аргументы, преобразуют их в байтовые команды и отправляют датчику.
   7. Группа методов стрима: “stream_start”, “stream_stop”, “stream_toggle_pause”, “set_active_sensor_for_stream”, “get_stream_value”, “get_stream_value_with_timeout”, “get_last_known_value”. Управляют фоновым потоком и отдают последние полученные значения.

3. Функции интерфейса и утилиты
   1. `print_header`, `print_main_menu`, `print_menu` — отрисовка текстовых меню.
   2. `handle_menu` — диспетчер выбора, вызывает методы SensorClient и форматирует вывод.
   3. `stream_loop` — цикл отображения стрима в реальном времени. Работает в отдельном потоке ввода, чтобы не блокировать отрисовку.
   4. `_input_num`, `menu_numeric` — проверка числового ввода.
   5. `kbhit_windows`, `_getch_linux` — кроссплатформенный перехват нажатий клавиш без буферизации.
   6. `main` — точка входа. Инициализирует клиент, разворачивает сервер, открывает TCP и запускает цикл главного меню.
